# 해상왕 장보고 런처

버전 **1.3.0**. 싱글 명령 지연 시험 패치, 마우스 가두기, 테두리 없는 전체화면, 16:9 표시와 카메라 거리 시험 옵션을 제공합니다.

테두리 없는 4:3 및 16:9 메뉴 출력을 확인했고, 사용자가 직접 클릭과 인게임 진행이 정상임을 확인했습니다. 카메라 옵션은 코드·x86 기본값·실제 프로세스 메모리와 시작 테스트를 통과했으나, 변경된 카메라로 플레이 시야·선택 좌표 검증은 아직입니다. 기본값은 원본 카메라이며, 거리 확장은 시험 옵션입니다.

## 창모드와 전체화면

런처에서 `창모드` 또는 `테두리 없는 전체화면`을 선택하고 게임을 실행하세요. 화면 설정 변경에는 게임 재실행이 필요합니다. **v1.2.0의 게임 자체 창모드 + 강제 확대 조합을 수정했습니다.** 게임은 전체화면 DirectDraw 표면을 요청하고, dgVoodoo가 이를 창모드/테두리 없는 창으로 출력합니다. 실제 독점 전체화면은 사용하지 않습니다. Alt+Enter 경로도 `fake` 전체화면으로 설정합니다.

`16:9 표시`는 원본 1280×960 화면을 1280×720 출력으로 가로 확장합니다. **네이티브 와이드 해상도 또는 가로 시야 확장 패치가 아닙니다.** 인물과 UI가 가로로 늘어나며, 해제하면 원본 4:3 비율로 돌아갑니다. 1280×720을 게임 INI에 직접 지정하는 방법은 디스플레이 초기화 오류로 제외했습니다.

### 카메라 거리 (시험)

`기본 / 1.25배 / 1.5배` 중 선택합니다. 기본은 원본 그대로입니다. 지원 EXE의 해시와 원래 값(36)을 검사한 뒤 실행 중 메모리의 게임 카메라 기본 거리를 45 또는 54로 변경합니다. 카메라 각도와 FOV, 유닛의 실제 탐지 범위, 전장의 안개는 바꾸지 않습니다. 생성·새 맵·카메라 초기화 경로에 적용되며 저장 파일이나 연출 카메라는 다른 값을 사용할 수 있습니다. 새 싱글 게임에서 시험하고 멀티에서는 `기본`을 사용하세요. 멀리 보기에서 지형 잘림·선택 위치 문제 등이 있으면 기본으로 돌려 재실행하세요.

근거: 기본 거리 상수 `0x69D7BC`는 카메라 생성(`0x42E0E6`), 맵 초기화(`0x42F293`), 초기화(`0x42F43A`)에 사용됩니다. 카메라 필드 `+0x14`는 위치(`0x42E690`)와 투영(`0x42E5CD`) 계산에 함께 사용됩니다. 원본 EXE는 수정하지 않습니다.

`마우스 가두기`가 켜져 있으면 게임이 활성화된 동안 클라이언트 영역 안으로 커서를 제한합니다. **F8**로 해제/다시 가두기, **Alt+Tab**이나 최소화로 자동 해제합니다. 게임으로 돌아오면 다시 가둡니다. 런처가 이 기능을 관리하므로 게임 중 런처를 켜 두세요. 런처를 닫으면 제한이 해제됩니다.

게임 폴더의 `Changpogo.ini`와 `dgVoodoo.conf`는 최초 변경 전에 각각 `.launcher-display.bak`으로 백업됩니다. 원래 설정으로 돌아가려면 게임·런처를 종료하고 해당 백업을 원래 파일명으로 복원하세요. 게임 EXE는 수정하지 않습니다.

설정 전환·백업 보존·반복 적용, x86 카메라 기본값 및 기존 명령 지연 회귀 테스트를 제공합니다. 화면 확인은 computer-use로 실제 게임을 실행해 수행했습니다. 모든 맵·저장 파일·다중 모니터 조합의 호환성을 보장하지는 않습니다.

## 주요 기능

- 게임 실행 파일 자동 탐색 및 경로 저장
- 싱글 명령 지연 줄이기: 명령 묶음 처리 기준 200ms → 50ms, 시뮬레이션 진행량 1/4 보정
- 싱글에서는 로컬 시계를 사용하고, 멀티에서는 원본 스케줄러 사용
- 기존 실행 우선순위 보조 옵션 유지 (이것만으로 명령 지연이 개선되지는 않았음)
- GitHub Releases 우선, `update.json` 보조 방식의 자체 업데이트
- ZIP 검증, 기존 파일 백업, 실패 시 롤백, 자동 재시작
- 원본 `Changpogo.exe`와 게임 데이터는 변경하지 않음

## 반응 지연에 관하여

대상 빌드 SHA-256: `16E4C3D3D17438928839A09901A4159DA154EB0EC822C784856707B77F9F4B1F`.

게임의 `0x488BB3` 스케줄러에서 실행 중인 명령 버퍼 처리 경로를 분석했습니다. v1.1.0은 원본 프로세스를 일시 정지 상태로 생성한 뒤 해시와 명령어를 확인하고, 프로세스의 별도 메모리에 변경된 스케줄러를 설치합니다. 싱글 모드(`0x70E8C4 == 0`)에서만 사용하며 게임 EXE 파일은 수정하지 않습니다. 종료하면 패치도 사라집니다.

단순히 게임 전체 속도를 올리지 않도록, 명령 묶음당 누적하는 시뮬레이션 진행량을 1/4로 조정합니다. 기존 게임 속도 표와 100ms 시뮬레이션 틱 코드는 변경하지 않습니다. 로컬 명령 묶음의 시간 기준을 현재 시간으로 고정해 멀티용 시계 보정과 짧아진 주기가 충돌하지 않게 했습니다.

**실제 게임 플레이에서의 이동·공격 반응 시간은 아직 측정하지 못했습니다.** 이것은 전체 1초 지연의 원인이 확정되었거나 완전히 해결되었다는 뜻이 아닙니다. 명령 버퍼 이후 유닛 AI·이동 경로·애니메이션 대기가 남을 수 있습니다. 저장 게임이나 리플레이의 전체 호환성도 미검증이므로 우선 새 싱글 게임에서 비교하세요. 옵션 해제 후 재실행하면 원본 경로를 사용합니다.

검증: 실제 x86 원본/패치 스케줄러 에뮬레이션, 4개 속도에서 진행량 오차가 원본 한 묶음 이내인지 확인, 모의 명령 큐 대기 감소, 멀티 모드 1/2의 원본과 동일한 동작, 재배치·스택·보존 레지스터 확인. 실제 Windows 프로세스 시작·메모리 패치 설치·5초간 생존을 확인했습니다. 모의 큐 수치는 실제 유닛 반응 측정값이 아닙니다.

## 사용법

1. `ChangpogoLauncher.exe`를 실행합니다.
2. 경로가 다르면 `찾기`에서 `Changpogo.exe`를 선택합니다.
3. `싱글 명령 지연 줄이기 (시험 적용)`를 켜고 `게임 실행`을 누릅니다.
4. 새 배포 버전은 `런처 업데이트` 버튼으로 적용합니다.

## 빌드와 배포

```powershell
.\build.ps1
.\package.ps1 -Version 1.3.0
```

생성된 ZIP을 GitHub Release에 첨부하거나 `releases/`에 게시한 뒤 `update.json`의 버전·URL을 갱신합니다. v1.1.0은 `update.json`을 통한 저장소 ZIP 배포를 사용합니다.

개발 검증 도구는 `tools/`에 있습니다. `make_latency_patch.py`는 사용자가 설치한 동일 해시 게임에서 `latency.manifest`를 재생성할 수 있습니다. Python 개발 의존성은 `pefile`, `capstone`, `unicorn`이며 사용자 실행에는 필요하지 않습니다.
