# 해상왕 장보고 런처

버전 **1.1.0**. 싱글플레이 이동·공격 명령의 버퍼 대기를 줄이는 시험 패치와 런처 업데이트 기능을 제공합니다.

## 주요 기능

- 게임 실행 파일 자동 탐색 및 경로 저장
- 싱글 명령 지연 줄이기: 명령 묶음 처리 기준 200ms → 50ms, 시뮬레이션 진행량 1/4 보정
- 싱글에서는 로컬 시계를 사용하고, 멀티에서는 원본 스케줄러 사용
- 기존 실행 우선순위 보조 옵션 유지 (이것만으로 명령 지연이 개선되지는 않았음)
- GitHub Releases 우선, `update.json` 보조 방식의 자체 업데이트
- ZIP 검증, 기존 파일 백업, 실패 시 롤백, 자동 재시작
- 원본 `Changpogo.exe`와 게임 데이터는 변경하지 않음

## 반응 지연에 관하여

대상 빌드 SHA-256: `16E4C3D3D17438928839A09901A4159DA154EB0EC822C784856707B77F9F4B1F`.

게임의 `0x488BB3` 스케줄러에서 실행 중인 명령 버퍼 처리 경로를 분석했습니다. v1.1.0은 원본 프로세스를 일시 정지 상태로 생성한 뒤 해시와 명령어를 확인하고, 프로세스의 별도 메모리에 변경된 스케줄러를 설치합니다. 싱글 모드(`0x70E8C4 == 0`)에서만 사용하며 게임 EXE 파일은 수정하지 않습니다. 종료하면 패치도 사라집니다.

단순히 게임 전체 속도를 올리지 않도록, 명령 묶음당 누적하는 시뮬레이션 진행량을 1/4로 조정합니다. 기존 게임 속도 표와 100ms 시뮬레이션 틱 코드는 변경하지 않습니다. 로컬 명령 묶음의 시간 기준을 현재 시간으로 고정해 멀티용 시계 보정과 짧아진 주기가 충돌하지 않게 했습니다.

**실제 게임 플레이에서의 이동·공격 반응 시간은 아직 측정하지 못했습니다.** 이것은 전체 1초 지연의 원인이 확정되었거나 완전히 해결되었다는 뜻이 아닙니다. 명령 버퍼 이후 유닛 AI·이동 경로·애니메이션 대기가 남을 수 있습니다. 저장 게임이나 리플레이의 전체 호환성도 미검증이므로 우선 새 싱글 게임에서 비교하세요. 옵션 해제 후 재실행하면 원본 경로를 사용합니다.

검증: 실제 x86 원본/패치 스케줄러 에뮬레이션, 4개 속도에서 진행량 오차가 원본 한 묶음 이내인지 확인, 모의 명령 큐 대기 감소, 멀티 모드 1/2의 원본과 동일한 동작, 재배치·스택·보존 레지스터 확인. 실제 Windows 프로세스 시작·메모리 패치 설치·5초간 생존을 확인했습니다. 모의 큐 수치는 실제 유닛 반응 측정값이 아닙니다.

## 사용법

1. `ChangpogoLauncher.exe`를 실행합니다.
2. 경로가 다르면 `찾기`에서 `Changpogo.exe`를 선택합니다.
3. `싱글 명령 지연 줄이기 (시험 적용)`를 켜고 `게임 실행`을 누릅니다.
4. 새 배포 버전은 `런처 업데이트` 버튼으로 적용합니다.

기본 경로는 `C:\Users\seo\Downloads\DGGL\Games\Changpogo_Win_260708\Changpogo.exe`입니다.

## 빌드와 배포

```powershell
.\build.ps1
.\package.ps1 -Version 1.1.0
```

생성된 ZIP을 GitHub Release에 첨부하거나 `releases/`에 게시한 뒤 `update.json`의 버전·URL을 갱신합니다. v1.1.0은 `update.json`을 통한 저장소 ZIP 배포를 사용합니다.

개발 검증 도구는 `tools/`에 있습니다. `make_latency_patch.py`는 사용자가 설치한 동일 해시 게임에서 `latency.manifest`를 재생성할 수 있습니다. Python 개발 의존성은 `pefile`, `capstone`, `unicorn`이며 사용자 실행에는 필요하지 않습니다.
