# Follow-up: v1.4.4 host test

The user reports no noticeable improvement with both peers enabling lead 3->2.
Local follow-up diagnostics contain 65 active multiplayer samples: 59 in network
state 3 and six in state 4. The submitted-minus-consumed counter difference is
2 in 64 samples and 1 in one sample. Reads are non-atomic; the latter is not proof
of a fault. This supports actual application of the lead change on the host.

The existing launcher samples approximately once per second and contains no
input timestamps or command execution timestamps. It cannot attribute a perceived
one-second delay to transport, command batching or execution. A successful patch
installation is NOT evidence of reduced end-to-end latency. Do not call v1.4.4 a
confirmed latency fix, nor assume the network is at fault.

Capture v2 adds 20ms samples of scheduler lead fields and outgoing command byte
count, based on the original code at 0x448772 and its caller 0x450C80. It reads only
numeric counters; no commands, player data, packets or raw dumps are published.
This can reveal prolonged queue occupancy but cannot identify individual commands
or directly measure click-to-movement latency. New matched host/client traces are
needed before choosing another runtime patch. Display and gameplay code have not
been changed in this follow-up.
